# v42 사전 분석 계획

**검증 질문.** 같은 물체에서 접촉 장치가 명목 높이를 조금 벗어날 때 이전에 무해했던 주변 contour가 실제 stick event를 바꾸는가? 이때 전체 query profile을 쓰는 original에 비해 estimated projection이 손해인 조건이 있는가? 과거 결과로 학습해 동결한 세 가지 correction의 selector는 동일 decoder에서 항상 0%를 적용하는 방법을 이기는가?

**설계.** 새 catalog panel 12개, panel당 시작 방향을 번갈아 한 block, flare/roll, 명목 19/31 mm, base/hollow/bulge, saturating/crossover의 24개 cell, 두 표면 방향, strong/weak/null regime, 8개 환경과 환경당 128개 배포 물체, 동일 noise 8회다. v41과 독립인 calibration·deployment·passive profile과 QMC seed를 쓴다. Law와 모양의 생성 family는 v41과 공유한다. 실제 접촉 높이는 명목값 + δ이며 δ(mm)의 순서는 −1, −0.5, −0.25, −0.125, 0, +0.125, +0.25, +0.5, +1이다. 한 δ는 하나의 체계적 placement error 시나리오이며 독립 물체당 jitter를 추출한 설계와 구별한다. Sensor의 일곱 좌표, 4회 calibration, factual evidence와 물체, acquisition 결과, noise, passive pair, source bank와 decoder의 명목 높이는 δ 간 동일하다. 따라서 δ가 바꾸는 것은 실제 사건이다. 방향만 아는 oracle projection도 함께 평가한다. 알려진 변형 축이 downstream risk를 최소화한다는 가정은 두지 않는다.

**물리적 변화와 projection.** (1) 같은 signed δ에서 hollow 또는 bulge의 label과 base의 label이 다른 비율을 event flip으로 정의한다. 같은 contour에서 δ=0과 비교한 변화도 따로 낸다. (2) 보정 없는 estimated−original Brier를 주 geometry 대조로 둔다. 양수면 projection이 손해다. 각 signed δ에서 24 cell을 동일 가중한 평균을 제시하고 9개 대조에 동시 양측 95% Bonferroni–t 구간을 낸다. Shape × 명목 높이 × signed δ의 36개 대조에도 별도 동시 구간을 적용한다. 방향별로 가장 작은 시험 offset에서 부호가 확인됐는지, 다음 값에서 다시 바뀌는지를 기재한다. 시험점 사이의 임계값을 연속적으로 단정하지 않는다. 명목값에서부터 손해인 무변형 물체와, 0에서 이득이었다가 δ에서 손해로 바뀐 형상·높이를 구별한다. Regime·law·variant별 추가 탐색은 보조 분석이다.
(3) 동일 예측 pₑ,pₒ에 대해 projection Brier 차이의 변화 Dδ−D₀=−2·mean[(pₑ−pₒ)(Yδ−Y₀)]를 원자료로 재구성한다. Yδ−Y₀를 (Yvariant,δ−Ybase,δ)+(Ybase,δ−Ybase,0)로 나눠 외곽 형상이 만드는 flip과 base 자체의 높이 이동이 각각 설명하는 양을 계산한다. 이 항등식은 통제된 simulator 안의 변화량을 귀속하는 도구다.

**세 보정 정책.** 0%, fixed 32.5%, v38 source gain optimizer 중 하나를 환경·관측 실현별로 선택한다. 방법은 source에서 확정하고 v42 결과를 보기 전 SHA-256으로 봉인한다. Offset 값, 실제 contact label, law 이름은 운영 selector에 주지 않는다. 원래 v38 보정식·β·gain table은 유지한다. 주요 operational 대조는 **estimated decoder 내 selector−always-zero**의 Brier이다. 0을 제외한 8개 signed δ를 균등 가중하고 각 panel에서 모든 하위 단위를 먼저 평균한다. 12개 panel, df=11의 paired t 95% 구간 상한 <0이면 우위, 최소 실용 감소량은 0.003이다. δ=0과 9개 전체 평균도 별도로 낸다. Signed δ별 selector−zero 9개에는 별도 동시 보정을 쓴다. Fixed·항상 optimizer, original 및 analytic direction oracle과의 비교도 제공한다. 12개 panel은 독립 단위이며 8개 noise와 9개 δ를 표본 수에 더하지 않는다.

**계산 비용.** 같은 유휴 GPU, 1,024개 물체 batch, 4회 calibration, 구입된 view/probe 비율을 고정한 end-to-end warm p90을 비교한다. 12개 cluster × 순서를 섞은 4회 측정. Selector는 실제로 보정 선택까지 포함하며 zero 경로는 불필요한 보정 계산을 생략한다. Cold에는 이미 획득한 profile의 direction fit과 높이별 template setup을 포함한다. 물리 readout·정렬·bank 최초 생성 시간은 별도다. Warm p90 selector / zero의 paired panel bootstrap 95% 구간 상한 ≤1.02이면 허용 overhead 이내로 판정한다. Brier와 latency를 서로 다른 단위로 공개한다.

**보조 대조.** 같은 환경에서 offset 값을 알려 주면 camera 좌표는 그대로 두고 source bank의 query event만 실제 높이에서 재계산할 수 있다. 모든 12 panel·24개 cell에서 같은 물체 index 0–31, noise index 0, 0% correction을 사용해 matched CPU subset으로 이를 점검한다. Source bank의 shape/law 가정은 유지한다. 따라서 이 control은 모든 물리 상태를 아는 oracle과 다르다. 주 측정·threshold는 이 결과로 수정하지 않는다. 과거 label을 쓴 selector와 v42 label을 쓴 사후 최선 선택은 구분한다.
